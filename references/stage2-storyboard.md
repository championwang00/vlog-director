# 阶段 2 · Claude 分镜导演

输入：阶段 1 的素材时间线 + 用户讲的故事线 + 音乐文件。
输出：`<项目>-storyboard.json`（剧本数据，唯一来源）和 `<项目>-storyboard.html`（可播放的分镜预演）。

## 2.0 先交「分镜理解稿」（用户确认后再往下做）

拿到 GPT / Codex 返回的内容后，先深入思考，再把理解给用户看。这一步只出方案，**不写预演页、不导交接包**。用户觉得不对就调整方案再给一次，直到他说可以。

理解稿包括：
1. **我理解的故事**：一句话主题 + 用户要的情绪起伏（例如「开心 → 挫折 → 低谷 → 坚持 → 还跑」）。
2. **分段方案**（表格）：段落、大致时长、用哪些素材（编号 + 一句画面）、为什么选它、原声还是画外音、音乐在这一段做什么。
3. **钩子和结尾**：开头 3 秒放什么，最后一句怎么收。
4. **取舍**：哪些好素材没用上、为什么；素材不够的地方打算怎么补（照片、Live、字卡）。
5. **拿不准、需要用户确认的**：事实（人名、里程、时间）、转写里标「待核」的句子、需要用户填的个人信息。
6. **总时长估算**，以及超了打算从哪里收。

用简短的表格和要点呈现，让用户几分钟能看完、能直接指出哪里要改。

## 2.1 剧本

### 故事结构（千岛湖验证过的骨架）

| 段落 | 作用 | 千岛湖的做法 |
|---|---|---|
| 钩子 ≤3 秒 | 倒叙最狼狈的一句原声 | 「还有 2 公里，但我的膝盖已经废了。」 |
| 黑屏字卡 | 时间倒回 | EVA 式「二十小时前」，右下「领物日」 |
| 第一幕 · 开心 | 我是谁 → 来干嘛 → 为什么有信心 → 目标 | 领物、吉祥物、名字墙、「我觉得自己能飞」、立下「二十分钟追上查理」 |
| 第二幕 · 小挫折 | 自嘲，第一次打脸 | 堵车、爬坡；CP1「落后 21 分钟，追不上查理了」 |
| 第三幕 · 高光 | 第一段副歌 | 快门拍下千岛湖、「值了」、CP2 喝粥 |
| 第四幕 · 低谷 | 原声为主，音乐沉下去 | 髂胫束痛、放下四小时目标、表情狰狞 |
| 第五幕 · 跑起来 | 最后副歌砸进来 | 朋友喊「跑起来」，冲线 |
| 复盘 | 高光闪回 | 起跑开头、冲线结尾，中间是最好看的赛道画面 |
| 收尾 | 一问一答 | 「下次，还来跑吗？」黑屏，「还跑」 |

### 写作规则
- **伏笔要回收**：前面埋的（旧伤、护膝带、目标时间、追朋友）后面都要被现实打脸或回应。可以用同一个句式反复出现（「我以为，追得上」「那时我以为，那是保险」）。
- **原声能讲清的地方不加画外音**。画外音只补三类：观众不知道的背景、后面要回收的伏笔、原声没讲到的感受。
- **信息递进**：开场介绍按「我是谁 → 来干嘛 → 为什么有信心 → 目标」排，不要一口气堆完；连续画外音之间插一句原声让观众喘口气。
- **用户的个人信息用【】留空**，字幕里也保留【】，让用户自己填。
- **画外音时长按每秒约 4 个字估**。按每秒 5–6 个字估，七成句子会超时。
- **前后矛盾要主动指出**（例如有 ITRA 积分，就不能说「第一次跑越野」）。
- 用户要求更有感染力时：先立一句主题（「所有的计划，都会在某段山路上被改写」），结尾回收（「走不动，就走。只要还在往前」）。
- 总时长守在用户给的上限内。加镜头就要说明从哪里收回了时间。

### 剧本 JSON（每个镜头一条）
`no`（镜头号）、`act`（段落）、`src`（源文件）、`in` / `out`（源入出点）、`speed`、`start` / `dur`（成片时间）、`visual`（画面处理）、`why`（为什么放）、`audio_type`（原声 / 画外音 / 纯音乐 / 静音）、`audio_note`、`volume`、`subtitles`（文本、起止、类型）、`vo`（画外音台词）、`packaging`（包装条目）、`flags`（待核、加速、打码等）。
预演页、交接包、录音清单都**从这份 JSON 生成**，不要在多个地方手改。改脚本时**以上一版为底稿**重新生成，免得丢掉之前在下游文件里手改过的内容。

## 2.2 原声定位
- 关键句子要逐字定位时间：Whisper 不带提示词识别一次，带领域提示词（如「越野跑、补给站、CP2」）再识别一次，两次对照；再用人声频段（300–3000 Hz）的能量曲线核对字的起止。
- 提示词会把结果往你想要的方向带，必须用不带提示词的结果交叉验证。
- 入点要从目标句的第一个字开始。千岛湖开场曾截到上一句「二十三公里」里的「三」，开头冒出一个「三」，按上面的方法改到 3.62 秒才解决。
- 风噪很大的自拍要先按人声频段滤波，再找说话的位置。

## 2.3 分镜预演网页（用户的主界面）
用户看不了纯文字剧本，必须是**能播放**的页面：
- **预演播放器**：竖屏手机框，按剪辑顺序播放真实画面和原声，字幕逐句出现（白字是原声，黄色斜体是画外音）；照片镜头有快门声和白闪；空格播放 / 暂停，← → 切镜头；右侧同步显示当前镜头的画面说明、为什么放、声音、字幕、包装、待核提示。
- **胶片时间线**：格宽 = 镜头时长；下面一条色带标原声 / 画外音 / 音乐；BGM 波形和节拍刻度；每一刀标出离最近节拍多远（绿：卡上了，黄：略偏，红：建议挪）；低通段用别的颜色标出来。
- **分镜画板**：按幕分组的竖屏卡片，字幕压在画面上；有包装的卡片角上标 ✦ 数量。
- **对照表**：「画外音 × 画面」对照表、包装总表（点一行跳到对应镜头）。
- **同步**：有音乐的段落，画面**跟着音乐的播放进度走**，音乐没出声时画面先等；换段用**两个音频播放器真叠化**。
- 用 `.claude/launch.json` 起本地服务预览；每次改完在浏览器里实测（每秒采样播放时间 / 音量 / 滤波频率，跳到关键镜头核对），再告诉用户「刷新，点第 N 镜看」。
- 用户说某几个画面看不到，就把它们做成一张**静态一览页**直接发过去。

## 2.4 音乐
- 只用无加密音频（mp3 / m4a / wav / flac）。.ncm 这类加密格式不转换，请用户换文件；正式发布时建议用平台曲库里的正版。
- 用 ffmpeg 分析 BPM、小节线、段落的真实时间（千岛湖用的《Fun》是 136 BPM），把剧本里估算的音乐时间换成真实的。
- **关键卡点**：第一段副歌对第一个高光动作（快门）；最后副歌在「跑起来」后第一刀砸进来；冲线落在全曲能量最高的小节；收尾那句说完落在重拍上。每个卡点报出误差（目标 < 0.05 秒）。
- **低谷段「沉到水下 → 破水而出」**：副歌不断，2 秒内加低通到约 380Hz、音量降到约 18%；转入安静桥段时继续保持闷音；「加油 → 跑起来」时滤波慢慢打开；最后副歌进场那一拍完全打开、音量推满。
- **少拼接**：用户对音乐断点非常敏感。能用原曲里一整段连续音乐走完，就不要拼；必须换段时，放在**最安静**的地方，在小节线上用两条轨叠化 1 个小节。冲线这种高能量处**绝不切音乐**。
- **收尾渐强**：从收尾那句一出现就开始推（用原曲自带的上扬小节），说完正好落在副歌重拍上，不要等到最后一幕才突然变大。
- 说话时音乐压到约 35%，纯音乐段 100%。

## 2.5 包装设计
- 全部用剪映自带的音效、转场、花字、贴纸、特效。每一条写清：时间、内容、剪映里搜什么、音量、为什么。千岛湖最后一共 85 处。
- **开场危机感**：低沉氛围音 + 心跳 / 喘气渐强 → 「废了」那一下重击 → 切黑时所有声音瞬间抽空 → 倒带音效配倒带画面（六段倒放快闪）。
- **第一、二幕逗趣**：起飞「嗖」声、「啊哦」配问号贴纸、立 FLAG 定格、吉祥物配「这吉祥物……？」。
- **低谷段克制**：少音效，只留风声和脚步。
- **照片展示**（所有照片镜头统一）：快门「咔嚓」+ 2 帧白闪；照片等比缩小到宽不超过 930px、高不超过 1650px（1080×1920 画布），居中放在**纯黑底**上，**上下左右四边都留黑**，可加 3px 细白边，慢推近时最大也要留黑。**不是暗角、不是烧边、不用模糊背景填充。**
- **Live 照片**：先全屏播 1–1.5 秒动态，快门那一刻 0.2 秒内缩成上面的照片尺寸定格；把快门时刻对到音乐拍点上。
- **大字卡**：EVA 式排版，见 `eva-typography` 技能（思源宋体 Heavy，拉成高瘦，贴左上角，同组字一样大，右下角放小字，形成对角呼应；硬切出现，配打字机音逐字出）。
- **不加任何滤镜、调色、胶片质感**。只允许一闪而过的情绪效果（如 0.6 秒黑白、一次红色暗角闪）。
- 隐私：名字墙等画面里，要留下的人保留清晰，其他人的名字全部模糊；保留原声。

## 2.6 外部制作的成品素材
剪映做不好的效果，由 Claude 用本机工具做成成品素材，放在 `fx/` 里，交给 Codex 直接替换：
- **抠像 + 运动模糊**：用 macOS Vision 抠出人物，背景单独模糊，再叠回去。模糊方向要**顺着人前进的方向**；脚下保留一片清晰的地面并羽化过渡，**模糊由近到远渐强**，抠像边缘羽化，避免「人飘在背景上」。旋转模糊以人为中心。
- **打码视频**：逐帧识别要保留的人，其他区域模糊。注意打码后的视频可能丢音轨，要把原声合回去。
- **长段文字**（比如片尾滚动的成绩信息）：直接渲染成透明 PNG，让 Codex 当图片用，比在剪映里排版快得多。
- 磁盘空间不够时 Vision 会直接返回全黑遮罩，先查 `df -h`。
