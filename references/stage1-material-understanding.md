# 阶段 1 · GPT 理解素材 → 素材时间线

目标：在动剧本之前，先把**每一份素材是什么、说了什么、发生在什么时候**整理成一个能浏览、能搜索的网页。后面的剧本、分镜、交接包都从这里取素材编号和原声。

千岛湖项目里，这一步是在 GPT 里做的，产出 `qiandaohu-go-ye-timeline.html`：63 份素材（47 段视频 + 16 张照片），视频原长合计 7 分 13 秒，分两天、七个阶段。

## 怎么跑

优先用本机 Codex CLI，由 Claude 启动、后台运行（命令格式见 stage3 文档）：

```bash
C=/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex
cd "<素材文件夹>"
nohup $C exec -m gpt-6.2-sol -s danger-full-access --skip-git-repo-check -C "$PWD" \
  --color never -o understanding_last_message.md \
  "请完整阅读 UNDERSTAND.md 并执行到底，不要中途停下来询问。" > understanding_run.log 2>&1 &
```

`UNDERSTAND.md` 由 Claude 按下面的「给 GPT 的任务说明」写好，放在素材文件夹里。
用户也可以自己在 ChatGPT 里做好再交给 Claude，那就跳过这一步，直接进入「Claude 验收」。

## 给 GPT 的任务说明（UNDERSTAND.md 模板）

```markdown
# 任务：理解素材，生成素材时间线网页

素材文件夹：<路径>。只读，不移动、不改名、不删除任何素材。

## 要做的
1. 盘点全部视频和照片。用 ffprobe / exiftool 读出：时长、分辨率、方向、拍摄时间（换成当地时间）、
   相机型号（区分本人手机、朋友手机、摄影师相机）、iPhone 照片是否带 Live Photo 编号。
2. 每段视频抽 3–6 张关键帧，每张照片做缩略图；看图写画面描述。
3. 用本机 Whisper 转写全部原声，按句给出起止秒数和说话人（我 / 同行者 / 现场对话 / 现场人声）。
   听不清的标「待核」，只能意会的写大意并标「意译」，不要编造。
4. 按天分组，再按事件分成阶段（例如：赛前会合、发枪开跑、进山爬坡、补给点、湖景村道、膝盖痛与完赛）。
5. 标出「主线候选」（最能讲故事的素材）和「可拆段」（一段素材里有两件事，给出切分秒数）。
6. 拍摄时间不可靠的（摄影师相机、导出后改了时间），按画面内容排序，并写明排序依据。

## 产出
`<项目名>-timeline.html`，单文件、离线可打开：
- 顶部：素材总数、视频段数、照片张数、视频原长合计。
- 筛选：全部 / 我的讲话 / 主线候选；搜索框能搜文件名、标题、描述和原声。
- 主体：按天 → 阶段 → 素材卡片排列；卡片显示时长或「照片」、拍摄时间、标题、描述、一句代表性原声、标签（主线候选 / 可拆段 / 时间约略）。
- 点卡片看详情：关键帧、全部原声（点时间点能回听）、拆段说明。
- 数据内嵌在 `<script type="application/json" id="media-data">` 里，字段见下。

完成后在 understanding_last_message.md 里写：总数、各阶段条数、待核句子数量、拿不准的地方。
```

## media-data 字段规范（每份素材一条）

| 字段 | 含义 | 示例 |
|---|---|---|
| `id` | 素材短编号，用文件名尾号；没有编号的用简写 | `"0770"`、`"fxn"` |
| `name` | 原始文件名 | `"IMG_0770.MOV"` |
| `short` | 卡片上显示的短名 | `"IMG_0770.MOV"` |
| `day` | 第几天 | `2` |
| `stage` | 阶段 id | `"prep"` |
| `clock` | 当地拍摄时间 | `"07:38:49"` |
| `timeNote` | 时间不可靠时的说明（空表示可靠） | `"摄影师相机时间偏差，按画面排在冲线前"` |
| `title` | 一句话标题 | `"同行者先往会场走"` |
| `desc` | 画面描述（人物、动作、景别、背景） | `"镜头先拍紫外套跑者的近景，他转身后沿彩虹路跑远。"` |
| `cover` | 封面缩略图（base64） | — |
| `main` | 是否主线候选 | `true` |
| `splits` | 可拆段：`[起, 止, 说明]` | `[[0,2.5,"路边说话告别"],[2.5,9.0,"沿彩虹路跑远"]]` |
| `dur` | 视频时长（秒）；照片为 `null` | `8.95` |
| `times` | 关键帧对应的秒数 | `[0.5, 2.6, 5.0, 7.8]` |
| `lines` | 原声：`[起, 止, 文本, 说话人·标注]` | `[0.0, 2.4, "先发枪了……", "我 · 意译"]` |
| `frames` | 关键帧缩略图（base64） | — |
| `audio` | 原声音频片段（供页面回听） | — |

页面里还要有一个 `days` 配置，定义每天的标题、日期和阶段（id、名称、时间范围），例如：

```js
{ id: 2, title: '第二天 · 实际比赛', date: '11 月 22 日', stages: [
  { id: 'prep',   label: '赛前会合与集结',     range: '07:34–08:07' },
  { id: 'start',  label: '发枪与湖边开跑',     range: '08:10–08:19' },
  { id: 'climb',  label: '进山、堵车与爬坡',   range: '08:41–09:37' },
  { id: 'cp1',    label: '第一处补给与后续赛道', range: '09:38–10:37' },
  { id: 'mid',    label: '湖景、村道与再次补给', range: '11:15–11:46' },
  { id: 'finish', label: '膝盖痛、返场与完赛',   range: '12:07–12:53' } ] }
```

## Claude 验收（进入阶段 2 之前必须做）

1. **读数据而不是读页面**：用正则取出 `media-data` 的 JSON，去掉 base64 再看，省上下文。
2. **对账**：JSON 条数 = 文件夹里的素材数；列出多出来的和缺的文件（用户后来补的素材经常不在里面）。
3. **抽查描述**：随机抽 3–5 条，自己抽帧看，核对描述。
4. **重听关键原声**：剧本可能当钩子或主线的句子，用 Whisper 再转写一遍，并做逐字时间定位（见 stage2「原声定位」）。标「待核 / 意译」的句子不要直接当字幕。
5. **Live Photo 清单**：列出带 Live 编号的照片。素材夹里通常只有 JPG，需要请用户在「照片」App 里选中这些照片，用「文件 → 导出 → 导出未修改的原件」导出。Claude 读不了系统照片图库。
6. 把发现的问题告诉用户，必要时让 GPT 补一轮；没问题就进入阶段 2。
