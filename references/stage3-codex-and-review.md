# 阶段 3 · Claude 调度 Codex 剪辑 + 逐轮验收

## 3.1 开工前确认环境
- Codex CLI：`/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`，先跑 `--version` 和 `login status`。
- 模型：用户说「Soul 模型」时指的是 **sol 系列**，用最新的 `gpt-6.2-sol`。**每次启动和接续都要显式写 `-m`**，否则会落到默认模型（千岛湖第一次接续就跑成了 `gpt-6-astra`，发现后立刻中断重来）。
- Codex 侧技能：`~/.codex/skills/xhs-jianying-edit`（剪映工程的做法和校验流程）。交接包里让它按这个技能执行。
- 剪映专业版版本：11.x 的草稿是**加密**的，不能从外部直接写工程文件。Codex 只能像人一样操作剪映界面，用剪映自带能力一步步搭（这也正好满足「能手动微调」）。
- 磁盘：`df -h`。剪映保存、朗读、导出都占空间，可用空间低于 20 GB 先提醒用户清理。
- 窗口：Mac 开了「台前调度」时，剪映失去焦点会被缩成侧边缩略图，Codex 就点不到界面。遇到时用 `open -a "剪映专业版"` 切回前台，不要改系统设置。
- 锁屏：Mac 锁屏后 Codex 操作不了界面。长任务前提醒用户，或者在本轮临时防休眠，结束后撤销。

## 3.2 交接包（项目里的 `jianying-handoff/`）

| 文件 | 内容 |
|---|---|
| `edit_plan_vN.json` | 从剧本 JSON 导出：镜头（源、入出点、目标时间码、速度、画面效果）、字幕（三条轨：原声 / 画外音 / 大字卡）、画外音、音乐段（源区间、叠化、音量和低通关键帧）、音效、包装、`photo_look`、`title_style_eva` |
| `BRIEF.md` | 第一轮的完整要求 |
| `RESUME-N.md` | 之后每轮：上一轮审片结论 + 新改动 + 本轮完成标准 |
| `fx/` | Claude 外部做好的成品素材 |
| `progress.md` | 让 Codex 边做边写进度，Claude 和用户都看这个 |
| `screens/` | Codex 的时间线截图 |
| `preview_vN.mp4` | 每轮导出的预览片，**不删**，旧的改名带版本号 |
| `REPORT.md` | Codex 每轮的报告：做了什么、哪些没能用剪映原生能力实现、遇到什么问题 |

### BRIEF.md 要点
- **独立新工程**，名称、比例（9:16，1080×1920，30fps），不动用户的其他工程。
- 数据以 `edit_plan_vN.json` 为准，按 `xhs-jianying-edit` 技能执行。
- 所有效果用剪映自带能力：分割、变速（保持音调）、音量和滤波关键帧、文本、音效库、转场、贴纸、花字、智能抠像、蒙版。
- 音乐：多条音乐轨交替放置，叠化处上下重叠，不在外部把音乐剪成一整条。
- 画外音：先空着（或按用户要求用剪映朗读）。字幕保留，方便用户录音时对位置。
- 不加任何滤镜和调色。
- 会员和积分功能：用户是剪映会员，可以用会员功能（如降噪、人声美化）。**不要购买任何东西**；会额外消耗积分的功能（如克隆音色朗读）先报告再用。
- 不删用户的任何文件；导出前先检查磁盘空间。
- 完成标准：保存后关掉剪映再重开，分段、关键帧、效果都还在；导出 `preview.mp4`；写 `REPORT.md`；截时间线全景和关键段落的图。

### RESUME-N.md 结构
```markdown
# 第 N 轮接续（数据：edit_plan_vM.json，草稿：「<草稿名>」）
## 先回复你上一轮的问题
## 先修：上一轮审片发现的问题（逐条：镜头号、成片时间、应该是什么、现在是什么、参照哪个版本）
## 用户新反馈（逐条，写清改哪一镜、怎么改、剪映里怎么做）
## 不要碰的地方（用户说「不用改了」的镜头）
## 完成标准（要抽哪些时间点的帧、和哪个版本对比、截图放进 REPORT.md；保存后重开确认）
```

## 3.3 启动、接续、中断

```bash
C=/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex
cd "<项目文件夹>"

# 第一轮
nohup $C exec -m gpt-6.2-sol -s danger-full-access --skip-git-repo-check -C "$PWD" --color never \
  -o jianying-handoff/codex_last_message.md \
  "请先完整阅读 jianying-handoff/BRIEF.md，然后按其中的要求执行到底，不要中途停下来询问。" \
  > jianying-handoff/codex_run.log 2>&1 &

# 之后每轮：接续同一个会话（会话 id 从第一轮日志或 ~/.codex/sessions 里取）
nohup $C exec resume <session-id> -m gpt-6.2-sol --skip-git-repo-check \
  -c 'sandbox_mode="danger-full-access"' \
  "请完整读取 jianying-handoff/RESUME-N.md 并在原剪映草稿「<草稿名>」上执行（数据来源 jianying-handoff/edit_plan_vM.json）。不删除任何 preview*.mp4。" \
  > jianying-handoff/codex_runN.log 2>&1 &

# 中断（这一轮在做已经过时的事，或模型不对）
kill -INT $(pgrep -f 'codex exec resume <session-id>' | head -1)
```

- 用 `run_in_background` 跑，结束时会收到通知；不要频繁轮询。
- 用户问「Codex 跑到哪了」：读 `progress.md` 和日志末尾，`ps -o etime=` 看运行了多久，如实汇报「已完成 / 正在做 / 还没做」。
- Codex 运行中**不能插话**。新改动存成下一版计划（v2、v3…）和下一个 RESUME，等这一轮结束再发。
- 中断后先确认它还没动手（日志里的 token 数没变），再带正确参数接续。

## 3.4 每轮验收（Claude 的审片清单）

1. **读 `REPORT.md` 和 `progress.md`**：它说做完的，逐条去验证，不直接相信。
2. **抽帧对照**：用 ffmpeg 在每个镜头中点抽帧，和分镜预演同一时刻的画面并排比较；重点看：
   - 镜头顺序、源文件、入出点对不对；
   - 有没有**退回旧版本**（剪映草稿偶尔会被改回去，要和上一版审片通过的预览对比）；
   - 照片四边留黑、Live 先动后定格、大字卡排版和字体。
3. **听**：
   - 音乐叠化处有没有断点或硬切（每 0.5 秒采样音量）；
   - 关键卡点误差（快门、副歌进场、冲线、收尾句）；
   - 原声有没有截到上一句、该有声音的镜头有没有声音（打码后的视频常常没音轨）；
   - 人声增强有没有真的加上（全片逐段跑一次语音识别，找出所有有人说话的片段，不要只看计划里标了原声的）。
4. **包装**：按包装总表抽查音效、转场、花字、贴纸是不是真的在轨道上（千岛湖第一轮一个转场都没加）。
5. **可编辑性**：在剪映里打开草稿，确认轨道能单独选中调整。
6. **结论**：通过就把预览片另存为 `preview_vN.mp4` 告诉用户；不通过就把问题按 RESUME 格式写下来，进入下一轮。

## 3.5 常见问题的处理
- **画外音超时**：克隆音色每秒约 4 个字，比估的慢。不要靠大幅加速硬压（最多 1.15 倍）；超时多的改台词或让用户自己录。用户决定自己录之后，删掉朗读片段，位置留空，字幕保留。
- **克隆音色朗读消耗积分**：千岛湖一次消耗了 189 积分。已经生成的不要重复生成。
- **会员功能**：Codex 默认会绕开带会员标识的功能。用户是会员，要在 RESUME 里明确写「可以用剪映会员的降噪 / 人声美化」，效果比外部处理再导入更好，之后也能在剪映里直接调。
- **剪映处理卡在 100%**：让 Codex 清掉卡住的任务后分批重跑。
- **用户说「这一镜不用改了」**：写进 RESUME 的「不要碰的地方」，审片时也跳过。
